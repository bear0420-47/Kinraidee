## Human-approved architecture decision

1. Replace the planned Cloudflare Pages, Koyeb API, and Koyeb PostgreSQL deployment with Firebase Hosting, Cloud Run, and Neon PostgreSQL.
2. Use Firebase Hosting for the Vite static web application, SPA fallback, and `/api/**` rewrite to Cloud Run so browser requests remain on one origin.
3. Deploy the stateless Express API to Cloud Run in `asia-southeast1` (Singapore) and begin with scale-to-zero plus a maximum of two instances.
4. Use Neon PostgreSQL in or nearest to Singapore. Use a pooled connection for Cloud Run runtime traffic and a direct connection for Prisma migrations.
5. Use Google Secret Manager for database credentials, JWT secret, Gemini and Google Places keys, and initial administrator credentials. Use Artifact Registry for immutable API images.
6. Keep production uploads disabled. Existing approved external menu-image URLs remain the production image source.
7. This architecture approval does not authorize public production deployment. Resource creation, secret transmission, migration against production, and public exposure require a separate explicit human approval.

## Reason

- The project owner has Google Cloud credits, making Cloud Run and Firebase Hosting cost-effective for the academic POC.
- Cloud Run matches the existing stateless Express API and can scale to zero.
- Firebase Hosting is designed for the current static Vite build and can proxy API paths to Cloud Run without changing the current same-site cookie design.
- Neon avoids Cloud SQL's continuous instance cost while retaining standard PostgreSQL and Prisma compatibility.
