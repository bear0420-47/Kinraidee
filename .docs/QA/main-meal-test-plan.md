## 2. ขอบเขตของรอบนี้

ทดสอบเฉพาะการเลือกอาหารแบบไม่ต้องเข้าสู่ระบบ ตั้งแต่หน้าแรกจนยืนยันเมนู รวมเส้นทางแก้เงื่อนไข เปลี่ยนเมนู และเริ่มใหม่ ผู้ทดลองไม่ต้องเปิดเครื่องมือของนักพัฒนาหรือส่งข้อมูลทดสอบด้วยตัวเอง

### เอาออกจากแผนรอบนี้ก่อน

- การยิง API, ตรวจ request/response, HTTP status, schema และ validation ที่ขอบเขต API
- การตรวจฐานข้อมูล sessionStorage และ log รวมถึงการตรวจข้อมูลที่บันทึกอยู่ภายใน
- การวัดความเร็ว API แบบ p95, cold start และทดสอบจำนวนข้อมูลมาก ๆ
- การจำลอง API ล่ม เครือข่ายล่ม ส่งคำขอซ้ำ หรือผลตอบกลับสลับลำดับ
- การทดสอบค่ารอยต่อราคาทุกค่าแบบอัตโนมัติ และการพิสูจน์อัลกอริทึมเลือกข้อเสนอที่ดีที่สุด

ส่วนนี้เป็นงานทีมพัฒนาหรือ QA และยังเป็น coverage gap ของการตรวจทั้งระบบ ไม่ใช่งานของผู้เข้าร่วมในฟอร์มนี้ การกดสุ่มแล้วเห็นว่าราคา/รส/ประเภท/โซนถูกต้องยังอยู่ในแผน เพราะเป็นผลที่ผู้ใช้เห็นโดยตรง

ไม่รวมสมัครสมาชิก บัญชี Favorites ประวัติ Admin GPS ค่าส่ง โหวตกลุ่ม การสั่งและจ่ายเงิน ส่วนปุ่มให้ระบบตัดสินใจแทนหนึ่งรายการยังไม่รวมจนกว่าจะยืนยันเส้นทางใช้งานตาม F12; ไม่ถือว่าปุ่มนี้เป็นสิ่งเดียวกับการรับการ์ดไม่เกินสามใบ

## 5. ทีมต้องเตรียมอะไร

1. เปิดแอปจริงและเช็กว่าเลือกอาหารได้ก่อนเริ่มรับผู้ทดลอง ใช้สภาพแวดล้อมทดสอบ ไม่แก้ข้อมูลจริงของผู้ใช้
2. เตรียมเมนูจำลองที่รู้ราคา รส ประเภท โซน และร้าน เพื่อใช้เทียบกับหน้าจอ ไม่ใช้ข้อมูลผู้เข้าร่วมเป็น fixture
3. ชุดปกติต้องมีเมนูตรงเงื่อนไขอย่างน้อย 4 รายการและอย่างน้อย 3 ร้าน เพื่อให้รับสามใบและเปลี่ยนได้อีกหนึ่งรายการ
4. ตัวอย่างชุดปกติ: งบ 50–100 บาท / รสเผ็ด / ข้าว / โซน A มีเมนูราคา 60, 70, 80, 90 บาทจากคนละร้าน เมนูผิดงบ ผิดรส ผิดประเภท หรือผิดโซนต้องไม่ปรากฏ
5. เตรียมอีกชุดสำหรับ UAT-05 ให้แก้เป็นเงื่อนไขใหม่แล้วมีผล และชุด UAT-08 ที่เงื่อนไขเดิมไม่มีผล แต่เงื่อนไขที่ระบบเสนอมีเมนูให้เลือกจริง
6. เตรียมคนอ่านโจทย์และคนจดผล/จับเวลา โดยไม่แนะนำว่าต้องกดปุ่มไหน
7. ใช้ [Consent form](participant-consent-form.md) ก่อนเริ่มเก็บข้อมูล แล้วตอบคำถามก่อนใช้ใน [UTAUT2.md](UTAUT2.md) จากนั้นลองใช้งานและตอบส่วนหลังใช้ การถามวิธีเดิมไม่ใช่การจับเวลาเปรียบเทียบก่อน–หลังจริง

## 6. รายละเอียดงานสำหรับผู้ทดลอง — ตรงตามฟอร์ม

ส่วนนี้ให้ลองใช้ Kinraidee ตามโจทย์ 8 ข้อ ตั้งแต่เลือกเงื่อนไข เปิดการ์ด เปลี่ยนเมนู เลิกทำ แก้เงื่อนไข ยืนยัน เริ่มใหม่ และลองกรณีไม่พบเมนู เรากำลังทดสอบแอป ไม่ได้ทดสอบความสามารถของคุณ ถ้าติดปัญหาให้บอกได้

ลองทำเองก่อน ให้ผู้ดูแลช่วยจับเวลาแต่ละงาน เริ่มเมื่อเริ่มทำ หยุดเมื่อเสร็จหรือหยุดลอง แล้วค่อยกลับมากรอกฟอร์ม ไม่นับเวลาที่กรอกฟอร์ม ถ้าไม่ได้จับเวลาให้เว้นไว้ ไม่ต้องเดา และถ้ามีคนช่วยให้บอกด้วย

ครั้งที่  8 มีรอบ 2 ซึ่งผู้ดูแลต้องเตรียมเงื่อนไขไว้ให้ ถ้ายังไม่มีข้อมูลพร้อมให้เลือก “ยังไม่ได้ลอง” ไม่ต้องเดาว่าผ่าน

### UAT-01 — ครั้งที่ 1: เลือกเงื่อนไขแล้วสุ่มอาหารด้วยตัวเอง

ข้อนี้อยากรู้ว่า: คุณเลือกเงื่อนไขแล้วสุ่มอาหารได้ด้วยตัวเองไหม ตั้งแต่หน้าแรกจนเห็นการ์ดเมนู

ให้ลองทำ: เริ่มจากหน้าแรก เลือกงบ 50–100 บาท ส่วนรสชาติ ประเภทอาหาร และโซน เลือกตามที่คุณต้องการ แล้วลองสุ่มอาหารจนเห็นการ์ดเมนู ถึงตรงนี้ให้หยุดก่อน ยังไม่ต้องเปิดการ์ดหรือเลือกว่าจะกินเมนูไหน

หลังลอง ให้ตอบด้านล่างว่าทำได้เองไหม ใช้เวลากี่วินาที และติดปัญหาตรงไหน ผู้ดูแลจะจับเวลาตั้งแต่เริ่มทำที่หน้าแรก จนเห็นการ์ดเมนูหรือหยุดลอง

ถ้าแอปแจ้งว่าไม่มีเมนูตรงเงื่อนไข ให้จดข้อความที่เห็นไว้ ไม่ต้องเปลี่ยนเงื่อนไขเพื่อให้ผ่าน

|---|---|---|
| UAT-01-1 | คุณเลือกเงื่อนไขแล้วสุ่มจนเห็นการ์ดเมนูได้เองไหม? | เลือกได้ข้อเดียว: ทำเสร็จเอง / ทำเสร็จ แต่มีคนช่วย / ทำไม่เสร็จ |
| UAT-01-2 | ใช้กี่วินาที? ใส่เฉพาะตัวเลข เช่น 45 (ถ้าไม่ได้จับเวลาให้เว้นไว้) | คำตอบสั้น |

### UAT-02 — ครั้งที่ 2: เปิดการ์ดและดูรายละเอียดเมนู

โจทย์: จากการ์ดที่ได้ ลองเปิดดูหนึ่งเมนูก่อน แล้วดูเมนูที่เหลือให้ครบ

ถือว่าทำเสร็จเมื่อ: เปิดทีละใบและเปิดทั้งหมดได้ เห็นชื่อเมนู ร้าน ราคา โซน และเหตุผลแนะนำ ข้อมูลตรงกับเงื่อนไขที่เลือกไว้ หากราคา รสชาติ ประเภท หรือโซนไม่ตรง ให้จดไว้

จับเวลา: จากการ์ดที่ยังไม่เปิดจนดูครบ หรือหยุดเพราะไปต่อไม่ได้

### UAT-03 — ครั้งที่ 3: เปลี่ยนเมนูที่ไม่อยากกิน

โจทย์: สมมติว่ามีหนึ่งเมนูที่คุณไม่อยากกิน ลองหาเมนูอื่นมาแทน โดยใช้เงื่อนไขเดิม

ถือว่าทำเสร็จเมื่อ: ได้เมนูอื่นมาแทนช่องเดิม เปิดแล้วไม่ซ้ำเมนูที่เพิ่งปฏิเสธหรือใบอื่นที่ยังอยู่ และยังตรงงบ รสชาติ ประเภท และโซนเดิม ผู้ดูแลต้องเตรียมให้มีเมนูอื่นเหลือพอ หากไม่มีให้บันทึกสิ่งที่แอปแสดง

จับเวลา: ตั้งแต่เริ่มเปลี่ยนจนเห็นรายละเอียดเมนูใหม่ หรือหยุดทำ อย่าเพิ่งยืนยันเมนู เพราะงานถัดไปจะลองเอาเมนูเดิมกลับมา

### UAT-05 — ครั้งที่ 5: แก้เงื่อนไขแล้วหาเมนูใหม่

ถือว่าทำเสร็จเมื่อ: เปลี่ยนเงื่อนไขได้ เห็นสรุปค่าที่แก้ และได้เมนูที่ตรงเงื่อนไขใหม่ โดยแอปไม่เปลี่ยนงบหรือโซนเอง ผู้ดูแลต้องเตรียมให้เงื่อนไขใหม่นี้มีเมนูให้เลือก

### UAT-06 — ครั้งที่ 6: เลือกเมนูและยืนยัน

เลือกเมนูที่สนใจ แล้วเข้าไปดูรายละเอียด
ลองกลับไปดูการ์ดเมนูอีกครั้ง โดยยังไม่ยืนยัน
เลือกเมนูที่ต้องการ แล้วยืนยันให้เสร็จ
ดูว่าเมนูที่แอปแสดงว่าเลือกสำเร็จ ตรงกับเมนูที่คุณเลือกไหม

## 7. วิธีอ่านช่องบันทึกผล

ฟอร์มมีตัวเลือกผลสำเร็จสามข้อ: ทำเสร็จเอง / ทำเสร็จ แต่มีคนช่วย / ทำไม่เสร็จ ไม่มีตัวเลือก “ยังไม่ได้ลอง” แม้คำชี้แจงตอนต้นจะกล่าวถึงตัวเลือกนี้ ถ้าข้อมูลไม่พร้อม ทีมต้องจด Not run หรือ Blocked แยกไว้ ไม่กรอกว่าทำไม่เสร็จแทนโดยไม่อธิบาย และไม่อ้างว่าได้ตรวจการข้ามหรือการบังคับตอบครบแล้ว

เวลาที่ไม่ได้จับให้เว้นตามคำถาม ไม่เดาหรือกรอก 0 แทน ไม่นับเวลาที่กรอกฟอร์ม กรณีที่ 1 และ 2 ของครั้งที่ 8 แยกบันทึกผล เวลา และปัญหา ไม่รวมเวลาของงานที่ไม่สำเร็จปนกับงานสำเร็จ

รายละเอียดโจทย์และช่องคำตอบด้านบนคัดจากฟอร์ม ส่วนการเตรียมข้อมูล ขอบเขต ระดับทดสอบ และเช็กลิสต์ทีมในเอกสารนี้เป็นข้อมูลประกอบที่ไม่ใช่คำถามเพิ่มให้ผู้ทดลอง

## 8. ขั้นตอนต่อคน

**Consent → คำถามก่อนใช้ → งานทดสอบทีละงาน → คำถาม UTAUT2 หลังใช้ → คำถามเสริมหลังใช้ตาม pain point**

ให้ผู้ใช้ลองเอง ไม่จับเมาส์หรือชี้ปุ่มแทน หากต้องช่วยให้บันทึกไว้ ถ้าพบว่าเลือกอาหารผิดเงื่อนไขหรือไปต่อไม่ได้ ให้จดปัญหา ไม่เปลี่ยนผลเป็นผ่านเพื่อให้ทดสอบต่อได้

คำถามก่อน–หลังและคะแนนคำนวณใช้ฉบับปัจจุบันใน [UTAUT2.md](UTAUT2.md) ไม่คัดรายการรหัสคำถามเก่ามาซ้ำ เพราะเวอร์ชันและบางข้อเปลี่ยนไปแล้ว

การจับเวลาในงานเหล่านี้เป็นเวลาทำงานผ่านหน้าจอจริง ส่วนคำถามก่อนใช้เรื่อง “ปกติใช้กี่นาที” เป็นความจำของผู้ตอบ จึงห้ามนำมาอ้างเป็นผล before/after ที่จับเวลาจริง

## 9. เกณฑ์สรุปและข้อจำกัด

- ทีมตรวจว่าผลตรงเงื่อนไขทุกใบ (NFR8), ไม่เกินสามใบ (NFR3), เปลี่ยนแล้วไม่ซ้ำเมื่อมีตัวเลือกเหลือ (NFR9) และผู้ใช้เลือกจนสำเร็จได้ ผลผิดเงื่อนไขถือเป็นปัญหาของระบบแม้ผู้ใช้บอกว่าทำเสร็จ
- ไม่สรุปจากคะแนน UTAUT2 ว่าฟังก์ชันผ่าน และไม่อ้างว่าได้ตรวจระบบทั้งแอปจากการทดสอบเฉพาะหน้าจอนี้
- NFR2 เดิมระบุผู้ใช้ขั้นต่ำห้าคน อย่างน้อย 80% จบ F1–F4 ภายใน 60 วินาทีโดยไม่ช่วย งานที่แบ่งกรอกทีละข้อมีช่วงพัก จึงไม่ใช้ผลรวมเวลาหรือเวลาที่ผู้ใช้เดามาอ้างว่าผ่าน NFR2 ต้องมีรอบจับเวลาต่อเนื่องและยืนยันจุดเริ่ม/จุดจบก่อนหากจะตัดสินเกณฑ์นี้
- งานที่ทำไม่ได้เพราะชุดข้อมูลไม่พร้อมให้เป็น Blocked; งานที่ยังไม่ทำเป็น Not run ไม่ใช่ Pass
- เรื่องภาพ/ข้อความตอนตัวแทนหมด ขอบช่วงงบที่กำกวม และเส้นทางแก้เงื่อนไขที่ยังไม่ชัด ให้ทีมตรวจเอกสารและยืนยันก่อนตัดสิน ไม่ใช้แอปที่ทำอยู่เป็นคำตอบแทน requirement
- รายการทดสอบเบื้องหลังที่เอาออกยังต้องมีหลักฐานแยกก่อนขออนุมัติปล่อยระบบ บันทึกผลจริงที่ไม่ระบุตัวบุคคลใน docs/verification.md ตามกติกาโปรเจกต์ ห้ามสร้างผลทดสอบขึ้นเอง

## 11. เปลี่ยนอะไรจากแผนเดิม 27 เคส

รอบก่อนมีการเขียนโครงใหม่ทั้งเอกสารเพื่อให้ผู้ทดลองอ่านง่าย จึงมี diff มากกว่าการลบเคส API เพียงอย่างเดียว: รวมเคสย่อยเป็นงานต่อเนื่อง ย่อข้อมูลจำลอง ลดตาราง traceability และตัดคำอธิบายเทคนิคบางส่วน ตารางนี้ทำให้เห็นว่าเคสเดิมย้ายไปไหน ไม่ควรเข้าใจว่าทุกบรรทัดที่หายไปเป็นฟังก์ชันที่ยกเลิก

### เช็กลิสต์เพิ่มเติมของทีม — ตรวจผ่านหน้าจอเท่านั้น

รายการเหล่านี้ยังไม่ทำให้ผู้ใช้ทุกคนต้องทำเกินแปดงาน หากยังไม่ได้ตรวจ ให้บันทึกว่า Not run แยกจากผล UAT

| รหัสทีม | สิ่งที่ตรวจ | ผลที่ควรได้ / ข้อจำกัด | อ้างอิง |
|---|---|---|---|
| UI-01 | ลองไปต่อโดยยังไม่เลือกเงื่อนไข | ไม่รับค่าที่ไม่ถูกต้อง และแจ้งให้แก้ที่ช่องเกี่ยวข้อง ไม่ส่งข้อมูลแปลก ๆ ด้วยเครื่องมือพิเศษ | F1; MAIN-08 |
| UI-02 | ใช้ชุดข้อมูลที่ตรงเงื่อนไข 0, 1, 2, 3 และมากกว่า 3 รายการ | เห็นจำนวนการ์ดตามผลจริง สูงสุดสาม ไม่มีการ์ดว่างที่แต่งขึ้น | F2, NFR3; MAIN-09 |
| UI-03 | เทียบราคาใกล้รอยต่อช่วงงบจากเมนูที่เปิดดู | ต้องตรงนิยามช่วงงบที่ยืนยันก่อน; ป้าย “ไม่เกิน 50” กับ “50–100” ยังต้องตกลงกรณี 50 บาท ไม่ใช้แอปเป็นตัวกำหนดคำตอบ | F1, NFR8; MAIN-07 |
| UI-04 | ดูสถานะขณะสับการ์ด | แสดงว่ากำลังทำงานตาม journey; ไม่กำหนด SLA ใหม่จากเวลาที่เห็นบนจอ | journey; MAIN-13 |
| UI-05 | เตรียมชุดที่ไม่มีเมนูใหม่เหลือให้เปลี่ยน | ไม่ฝืนเอาตัวที่ปฏิเสธแล้วหรือผิดเงื่อนไขกลับมาเติม; ข้อความปลายทางที่ยังไม่ระบุต้องยืนยันก่อนตัดสิน | F4, F5, NFR9; MAIN-16 |
| UI-06 | กลับ Home ระหว่างยังเลือกไม่จบ แล้วเริ่มทำต่อ | กลับมาทำ flow เดิมต่อได้ตาม journey ไม่ล้างเป็นรอบใหม่โดยไม่ตั้งใจ | F7, journey; MAIN-22 |
| UI-07 | ใช้คีย์บอร์ดตั้งแต่เลือกเงื่อนไขถึงยืนยัน | ไม่มีขั้นตอนติดขัด มี focus มองเห็น ไม่ต้องใช้เมาส์เพื่อไปต่อ | NFR12; MAIN-23 |
| UI-08 | อ่าน notice และลอง core flow โดยไม่ให้ consent ส่วนที่ optional | มีคำแจ้งการใช้เงื่อนไข และไม่บังคับยินยอมส่วนที่ไม่จำเป็น; แยกจาก consent เข้าร่วมศึกษา | LR1–LR3, F6; MAIN-26 |
| UI-09 | สังเกตรูปไม่ขึ้นหรือ refresh ระหว่างใช้ | บันทึกสิ่งที่เจอและการกู้คืน; พฤติกรรม fallback/restore ที่ยังไม่กำหนดเป็นข้อสังเกต ไม่ตั้งเกณฑ์ผ่านเอง | MAIN-27; exploratory |

ก่อนรันทดสอบจริง ทีมควรทบทวนเคสที่ AI ช่วยร่างทุกข้อ เอกสารและการย่อ/จัดกลุ่มครั้งนี้ใช้ AI ช่วย ผู้รับผิดชอบยังเป็นผู้ตรวจความถูกต้องและตัดสินผลจริง
