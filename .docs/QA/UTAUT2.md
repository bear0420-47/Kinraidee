# แบบประเมินการยอมรับ Kinraidee โดยประยุกต์จาก UTAUT2

**สถานะ:** Draft — ร่างสำหรับตรวจคำถามและทดลองแบบสอบถามก่อนเก็บข้อมูลจริง  
**วันที่จัดทำ:** 2026-10-05  
**สถานะการเก็บข้อมูล:** ยังไม่ได้ดำเนินการ

**ปรับปรุง 2026-10-21:** ใช้คะแนน 1–5 ตามที่เจ้าของโครงการกำหนด ให้ตอบหลังทดลอง main workflow; ปรับระดับคำตอบ ตัวอย่าง และสูตรคำนวณให้ตรงกัน การปรับนี้ไม่ใช่ผลการตรวจสอบคุณภาพเครื่องมือ

## 1. แบบประเมินนี้ใช้ตอบอะไร

แบบประเมินนี้ใช้ดูว่า หลังทดลอง Kinraidee ผู้ใช้เห็นประโยชน์ ใช้ง่าย และตั้งใจกลับมาใช้หรือไม่ รวมถึงดูว่าระบบช่วยลด pain point เดิมเรื่องการเลือกอาหารได้มากน้อยเพียงใด

UTAUT2 ย่อจาก **Unified Theory of Acceptance and Use of Technology 2** เป็นกรอบศึกษาการยอมรับและการใช้เทคโนโลยี ส่วนความพึงพอใจจะถามแยกอีกข้อหนึ่ง ไม่รวมเป็นตัวแปรเดียวกับการยอมรับ

คำถามในเอกสารนี้ปรับให้เข้ากับ Kinraidee จึงเป็นแบบประเมิน **UTAUT2-based** ไม่ใช่แบบแปลมาตรฐานที่ผ่านการตรวจสอบความเที่ยงตรงและความเชื่อมั่นแล้ว และยังไม่ได้ทดสอบโมเดล UTAUT2 ครบทุกองค์ประกอบ

ผลประเมินนี้แยกจาก functional test และการจับเวลาตาม NFR2: คะแนนการยอมรับสูงไม่ใช้แทนหลักฐานว่าระบบทำงานถูกต้อง

## 2. ตัวย่อแต่ละตัวหมายถึงอะไร

| ตัวย่อ | ชื่อเต็ม | วัดอะไร | ใน Kinraidee ควรถามอะไร |
|---|---|---|---|
| **PE** | Performance Expectancy — ประโยชน์ที่คาดหวังจากการใช้ | ระบบช่วยให้งานดีขึ้น เร็วขึ้น หรือมีประโยชน์ไหม? | ช่วยตัดสินใจเลือกอาหารได้ดีขึ้น เร็วขึ้น และลดภาระการคิด |
| **EE** | Effort Expectancy — ความง่ายในการใช้ | ระบบเรียนรู้และใช้งานง่ายไหม? | เรียนรู้และใช้ขั้นตอนเลือกอาหารได้ง่าย |
| **FC** | Facilitating Conditions — ความพร้อมและสิ่งสนับสนุน | มีอุปกรณ์ อินเทอร์เน็ต ความรู้ และความช่วยเหลือเพียงพอให้ใช้ได้ไหม? | มีสิ่งที่จำเป็นและแหล่งช่วยเหลือสำหรับใช้ Kinraidee |
| **HM** | Hedonic Motivation — แรงจูงใจจากความเพลิดเพลิน | ใช้แล้วสนุกหรือเพลิดเพลินไหม? | รู้สึกสนุกกับการเลือกอาหารและเปิดการ์ดเมนู |
| **SI** | Social Influence — อิทธิพลทางสังคม | คนที่เราให้ความสำคัญเห็นว่าเราควรใช้ระบบไหม? | เพื่อนหรือคนสำคัญมีความคิดเห็นสนับสนุนให้ผู้ใช้ใช้ Kinraidee |
| **BI** | Behavioral Intention — ความตั้งใจใช้ | ตั้งใจจะใช้ระบบอีกในอนาคตไหม? | ตั้งใจกลับมาใช้เมื่อตัดสินใจเรื่องอาหารไม่ได้ |
| **PV** | Price Value — ความคุ้มค่าด้านราคา | ประโยชน์คุ้มกับเงินที่จ่ายเพื่อใช้ระบบไหม? | ประโยชน์คุ้มกับค่าใช้บริการ Kinraidee หรือไม่ |
| **HT** | Habit — ความเคยชิน | ใช้ระบบจนเป็นนิสัยหรือใช้โดยแทบไม่ต้องคิดแล้วหรือยัง? | ใช้ Kinraidee จนเกิดความเคยชิน |
| **UB** | Use Behavior — พฤติกรรมการใช้จริง | กลับมาใช้จริงกี่ครั้ง บ่อยแค่ไหน และใช้ส่วนใด? | ผู้ใช้กลับมาเลือกอาหารด้วย Kinraidee จริงมากน้อยเพียงใด |

**แยกให้ชัด:**

- **PE กับ EE:** PE คือช่วยให้งานเลือกอาหารง่ายขึ้นหรือมีผลลัพธ์ดีขึ้น ส่วน EE คือใช้ตัวแอปง่ายหรือไม่
- **BI กับ UB:** BI คือความตั้งใจ ส่วน UB คือพฤติกรรมที่เกิดขึ้นจริง
- **PV กับงบอาหาร:** PV คือความคุ้มค่าของค่าใช้บริการแอป การแนะนำอาหารตรงงบเป็นประโยชน์ของระบบและประเมินในชุด pain point
- **SI กับการแนะนำเพื่อน:** SI คือคนอื่นมีอิทธิพลให้เราใช้ การที่เราอยากแนะนำแอปให้เพื่อนเป็นอีกประเด็นหนึ่ง

## 3. ขอบเขตการประเมินรอบแรก

ประเมิน core workflow: **Get a meal shortlist** ตาม journey ปัจจุบัน

1. เปิด Kinraidee โดยไม่ต้องเข้าสู่ระบบ
2. เลือกงบ → รสชาติ → ประเภทอาหาร → โซน
3. ใช้ `สับการ์ดเมนู` เพื่อรับตัวเลือกไม่เกินสามรายการ
4. เปิดการ์ด ลองเปลี่ยนตัวเลือกที่ไม่ถูกใจ และเลือกเมนู
5. ตรวจรายละเอียดและยืนยันตัวเลือก

รอบแรกให้ถาม PE, EE, FC, HM และ BI หลังทดลองใช้ และเก็บ SI เฉพาะผู้ที่มีข้อมูลความคิดเห็นจากคนรอบตัว ส่วน PV, HT และ UB ติดตามเมื่อเงื่อนไขพร้อม

**ส่วนที่ไม่ครอบคลุม:** การบริหารข้อมูลร้าน, favorites, history และ default settings ต้องมีภารกิจเฉพาะก่อนประเมินเพิ่มเติม ส่วน GPS/ระยะทาง ค่าส่ง รีวิว และการโหวตกลุ่มไม่ประเมินเป็นผลสำเร็จของ core workflow รุ่นนี้ การประเมินนี้ไม่รับรองความปลอดภัยหรือการปฏิบัติตามกฎหมาย

## 4. ขั้นตอนเตรียมและเก็บข้อมูล

1. กำหนดคำถามหลัก: “หลังทดลองใช้ ผู้ใช้รับรู้ประโยชน์ของ Kinraidee เพียงใด และตั้งใจใช้ต่อเพียงใด?”
2. เลือกนักศึกษาหรือผู้เลือกอาหารที่ตรงกลุ่มเป้าหมาย บันทึกวิธีคัดเลือกและจำนวนคน ไม่ใช้ทีมพัฒนาเป็นผู้ตอบหลัก
3. ทดลองคำถามกับกลุ่มเล็กประมาณ 5–8 คนเพื่อดูความเข้าใจ ตัวเลขนี้เป็นข้อเสนอสำหรับ pilot ไม่ใช่ขนาดตัวอย่างขั้นต่ำของงานวิจัย
4. ให้อาจารย์หรือผู้รู้ตรวจความตรงของคำถามกับตัวแปร ปรับและบันทึกเวอร์ชันก่อนเก็บจริง
5. ให้ผู้ใช้ทดลอง workflow ด้วยเงื่อนไขมื้ออาหารของตนเอง หากใช้สถานการณ์สมมติต้องระบุไว้ และเตรียมข้อมูลให้มีตัวเลือกอื่นสำหรับการเปลี่ยนเมนู
6. ให้ตอบหลังทดลอง โดยไม่ชี้นำว่าควรตอบคะแนนสูง บันทึกการช่วยเหลือและปัญหาระหว่างทดลอง
7. สรุปแยกตัวแปรและ pain point ไม่รวมเป็นคะแนน UTAUT2 ตัวเดียว

จำนวนขั้นต่ำห้าคนใน NFR2 เป็นเกณฑ์ usability ของโปรเจกต์ ไม่ใช่หลักฐานว่าตัวอย่างเพียงพอสำหรับ regression หรือ SEM หากต้องทดสอบโมเดลทางสถิติ ต้องวางแผนขนาดตัวอย่างและคุณภาพเครื่องมือเพิ่มเติม

ใช้รหัสผู้ตอบ เช่น P01 แทนชื่อ แจ้งวัตถุประสงค์และการจัดการข้อมูลก่อนเก็บ ไม่ใส่คำตอบดิบ อีเมล หรือข้อมูลส่วนบุคคลที่ไม่จำเป็นใน repository เก็บใน repository เฉพาะผลสรุปที่ไม่ระบุตัวบุคคลตามกติกาโปรเจกต์

## 5. ลำดับแบบสอบถามและระดับคะแนน

**บริบทก่อนใช้ → ทดลองระบบ → PE → EE → HM → FC → SI → BI → pain point → ความพึงพอใจ → คำถามปลายเปิด**

### คำชี้แจงสำหรับผู้ตอบ

> โปรดตอบจากประสบการณ์การใช้ Kinraidee ครั้งนี้ สำหรับคำถามเกี่ยวกับอนาคต ให้ตอบตามความตั้งใจของคุณ ไม่มีคำตอบถูกหรือผิด และคำตอบไม่มีผลต่อสิทธิในการใช้งาน

| คะแนน | ความหมาย |
|---|---|
| 1 | ไม่เห็นด้วยอย่างยิ่ง |
| 2 | ไม่เห็นด้วย |
| 3 | กลาง ๆ |
| 4 | เห็นด้วย |
| 5 | เห็นด้วยอย่างยิ่ง |

เพิ่มตัวเลือก **“ไม่ได้ทดลอง / ประเมินไม่ได้”** ซึ่งเป็นข้อมูลขาดหาย ไม่ใช่คะแนน 0 หรือคะแนนกลาง แบบประเมินของโครงการนี้ปรับเป็น **5 ระดับ** ตามคำสั่งเจ้าของโครงการ ส่วนงานต้นฉบับใช้ 7 ระดับ ดู [Venkatesh, Thong & Xu (2012)](https://doi.org/10.2307/41410412) ต้องระบุการปรับมาตราส่วนนี้ในรายงานและทดลองความเข้าใจของแบบสอบถามก่อนเก็บจริง

### 5.1 บริบทก่อนใช้ — ไม่คิดคะแนนรวม

| รหัส | คำถาม | รูปแบบคำตอบ |
|---|---|---|
| B1 | ปกติคุณเลือกอาหารไม่ออกบ่อยแค่ไหน? | ไม่เคย / น้อยกว่าสัปดาห์ละครั้ง / สัปดาห์ละ 1–3 ครั้ง / สัปดาห์ละ 4–6 ครั้ง / ทุกวัน |
| B2 | ก่อนทดลอง คุณมีเมนูที่อยากกินชัดเจนแล้วหรือยัง? | ไม่มีเลย / มีแนวคร่าว ๆ / มีหลายตัวเลือกแต่เลือกไม่ได้ / มีตัวเลือกชัดเจน |
| B3 | อะไรทำให้เลือกอาหารยากในครั้งนี้? | เลือกหลายข้อ: ไม่รู้ว่าอยากกินอะไร / ตัวเลือกเยอะ / เบื่อร้านหรือเมนูเดิม / จำกัดงบ / รสชาติไม่ตรง / ประเภทอาหารไม่ตรง / พื้นที่ไม่สะดวก / อื่น ๆ / ไม่มีปัญหา |
| B4 | ก่อนทดลอง คุณรู้สึกเหนื่อยจากการเรียน งาน หรือกิจกรรมอื่นแค่ไหน? | 1 ไม่เหนื่อยเลย ถึง 5 เหนื่อยมาก; เป็นระดับแยกจากคะแนนการยอมรับ |
| B5 | คุณเคยใช้แอปสุ่มอาหารมาก่อนหรือไม่? | ไม่เคย / เคย; ถ้าเคย ระบุจำนวนครั้งโดยประมาณ |
| B6 | ครั้งนี้ใช้อุปกรณ์ของตนเองหรือของทีม? | ของตนเอง / ของทีม / อื่น ๆ |

### 5.2 PE — ประโยชน์ต่อการเลือกอาหาร

เชื่อมกับ P1 ภาระการตัดสินใจ, P2 บริบทความเหนื่อย และ P8 ตัวเลือกตามเงื่อนไข

| รหัส | ข้อความให้ประเมิน |
|---|---|
| PE1 | Kinraidee มีประโยชน์ต่อการเลือกอาหารในชีวิตประจำวันของฉัน |
| PE2 | Kinraidee ช่วยให้ฉันตัดสินใจเลือกอาหารได้เร็วขึ้น |
| PE3 | Kinraidee ช่วยลดความพยายามที่ฉันต้องใช้ในการคิดว่าจะกินอะไร |
| PE4 | Kinraidee ช่วยให้ฉันได้ข้อสรุปว่าจะเลือกอาหารอะไรสำหรับมื้อนี้ |

PE2 และ PE3 เป็นประโยชน์ที่ผู้ใช้รับรู้ ไม่ใช่หลักฐานว่าระบบลดเวลาหรือภาระคิดได้จริงเมื่อเทียบกับวิธีอื่น การเปรียบเทียบต้องมีการออกแบบการวัดเพิ่มเติม

### 5.3 EE — ความง่ายในการใช้

ประเมินประสบการณ์ใช้ F1–F7 และตอบโจทย์ P8 ที่ต้องการกรอกเงื่อนไขสั้น ๆ

| รหัส | ข้อความให้ประเมิน |
|---|---|
| EE1 | ฉันเรียนรู้วิธีใช้ Kinraidee ได้ง่าย |
| EE2 | ลำดับขั้นตอนการใช้ Kinraidee ชัดเจนและเข้าใจได้ |
| EE3 | ฉันทำสิ่งที่ต้องการใน Kinraidee ได้โดยไม่ต้องใช้ความพยายามมาก |
| EE4 | ฉันคิดว่าจะใช้ Kinraidee ได้คล่องเมื่อใช้ครั้งต่อไป |

### 5.4 HM — ความสนุกและความเพลิดเพลิน

ประเมินรูปแบบการ์ดใน journey ปัจจุบัน เป็นมุมการยอมรับเพิ่มเติม ไม่อ้างว่า survey เดิมพิสูจน์ว่าผู้ใช้ต้องการความสนุก

| รหัส | ข้อความให้ประเมิน |
|---|---|
| HM1 | ฉันรู้สึกสนุกกับการใช้ Kinraidee |
| HM2 | ฉันรู้สึกเพลิดเพลินระหว่างเลือกอาหารด้วย Kinraidee |
| HM3 | รูปแบบการเปิดการ์ดเมนูทำให้การใช้ Kinraidee เป็นประสบการณ์ที่น่าสนุก |

### 5.5 FC — ความพร้อมและสิ่งสนับสนุน

เป็นบริบทการยอมรับเพิ่มเติมจาก survey เดิม ประเมินสภาพจริงและระบุว่าทีมเตรียมอุปกรณ์หรือช่วยผู้ใช้หรือไม่

| รหัส | ข้อความให้ประเมิน |
|---|---|
| FC1 | ฉันมีอุปกรณ์และการเชื่อมต่ออินเทอร์เน็ตที่จำเป็นสำหรับใช้ Kinraidee |
| FC2 | ฉันมีความรู้พื้นฐานเพียงพอที่จะใช้ Kinraidee |
| FC3 | Kinraidee ใช้งานร่วมกับอุปกรณ์และเบราว์เซอร์ที่ฉันใช้เป็นประจำได้ |
| FC4 | ฉันสามารถหาความช่วยเหลือได้หากมีปัญหาในการใช้ Kinraidee |

### 5.6 SI — อิทธิพลจากคนรอบตัว

เป็นมุมการยอมรับเพิ่มเติม ไม่ใช่การวัดฟีเจอร์โหวตกลุ่มตาม P9

ถามคัดกรองก่อนว่า **“มีคนใกล้ตัวที่รู้จักหรือเคยพูดคุยกับคุณเกี่ยวกับ Kinraidee หรือไม่?”** ถ้าไม่มี ให้ข้าม SI และบันทึกว่าไม่มีข้อมูล ไม่ให้เดาความคิดเห็นของคนอื่น

| รหัส | ข้อความให้ประเมิน |
|---|---|
| SI1 | คนที่สำคัญต่อฉันเห็นว่าฉันควรใช้ Kinraidee เพื่อช่วยเลือกอาหาร |
| SI2 | คนที่มีอิทธิพลต่อการตัดสินใจของฉันสนับสนุนให้ฉันใช้ Kinraidee |
| SI3 | คนที่ฉันให้ความสำคัญกับความคิดเห็นของเขาเห็นด้วยกับการที่ฉันใช้ Kinraidee |

### 5.7 BI — ความตั้งใจใช้ต่อ

เป็นผลลัพธ์การยอมรับเพิ่มเติมที่ต้องการวัด หากยังเป็น prototype ให้ระบุว่า **“สมมติว่า Kinraidee เปิดให้ใช้งานในรูปแบบที่ทดลองนี้”** ก่อนถาม

| รหัส | ข้อความให้ประเมิน |
|---|---|
| BI1 | ฉันตั้งใจจะใช้ Kinraidee อีกในอนาคต |
| BI2 | เมื่อเลือกอาหารไม่ออก ฉันตั้งใจจะใช้ Kinraidee เป็นตัวช่วย |
| BI3 | ในช่วงหนึ่งเดือนข้างหน้า ฉันวางแผนจะใช้ Kinraidee เมื่อมีโอกาสเลือกอาหาร |

## 6. คำถามเชื่อมกับ pain point เดิม

ใช้คะแนน 1–5 เหมือนกัน แต่รายงาน **แยกรายข้อ** ไม่รวมเข้ากับคะแนนตัวแปร UTAUT2 เพราะแต่ละข้อวัดประโยชน์ของคนละฟีเจอร์

| รหัส | ข้อความให้ประเมิน | Pain point | ฟีเจอร์ที่เกี่ยวข้อง |
|---|---|---|---|
| PP1 | จำนวนตัวเลือกที่แสดงช่วยให้ฉันเปรียบเทียบอาหารได้โดยไม่รู้สึกว่ามีตัวเลือกมากเกินไป | P3, P8 | F2 |
| PP2 | ตัวเลือกจากหลายร้านช่วยให้ฉันไม่ต้องพิจารณาแต่ร้านเดิม | P3 | F19 |
| PP3 | การเปลี่ยนตัวเลือกที่ไม่ถูกใจช่วยให้ฉันเดินหน้าตัดสินใจต่อได้ แม้ยังไม่รู้แน่ชัดว่าอยากกินอะไร | P4 | F4, F5 |
| PP4 | การกำหนดงบช่วยลดตัวเลือกที่ฉันไม่สามารถจ่ายได้ | P5 | F1, F2 |
| PP5 | การกำหนดรสชาติช่วยให้ตัวเลือกใกล้เคียงกับสิ่งที่ฉันอยากกิน | P6 | F1, F2 |
| PP6 | การกำหนดประเภทอาหารช่วยให้ฉันหาตัวเลือกที่เหมาะกับมื้อนี้ได้ | P6 | F1, F2 |
| PP7 | การกำหนดโซนช่วยให้ฉันพิจารณาร้านในพื้นที่ที่สะดวกสำหรับฉัน | P7 | F1, F2, F3 |

PP2 ใช้เมื่อเห็นตัวเลือกจากหลายร้าน และ PP3 ใช้เมื่อได้ลองเปลี่ยนตัวเลือก สำหรับเงื่อนไขที่ไม่ได้เลือกอย่างเฉพาะเจาะจงหรือประเมินไม่ได้ ให้เลือก “ประเมินไม่ได้”

### ความพึงพอใจรวม — แยกจาก UTAUT2

| รหัส | ข้อความให้ประเมิน |
|---|---|
| SAT1 | โดยรวม ฉันพึงพอใจกับการใช้ Kinraidee ครั้งนี้ |

### คำถามปลายเปิด

1. อะไรใน Kinraidee ช่วยลดการคิดของคุณได้มากที่สุด เพราะอะไร?
2. หลังใช้แล้ว คุณยังติดปัญหาในการเลือกอาหารเรื่องไหน?
3. มีข้อมูลอะไรที่ยังขาดและทำให้คุณตัดสินใจไม่ได้?
4. อะไรจะทำให้คุณกลับมาใช้ หรือไม่กลับมาใช้อีก?

ชุดรอบแรกมี **21 ข้อด้านการยอมรับ + 7 ข้อด้าน pain point + 1 ข้อความพึงพอใจ = 29 ข้อคะแนนสูงสุด** โดยบางข้อข้ามตามเงื่อนไข ไม่นับคำถามบริบท คัดกรอง และปลายเปิด

## 7. ส่วนที่ติดตามภายหลัง

### PV — เมื่อมีค่าใช้บริการที่ชัดเจน

ระบุราคาหรือแพ็กเกจเดียวกันให้ผู้ตอบก่อนถาม ความคุ้มค่าของค่าใช้บริการเป็นคนละเรื่องกับราคาของอาหาร หากแอปฟรีและยังไม่มีต้นทุนการใช้ที่เหมาะกับตัวแปรนี้ ให้ระบุว่าไม่ได้วัด PV ในรอบแรก

ตัวอย่างร่างสำหรับรอบที่มีราคา:

- PV1: ค่าใช้บริการ Kinraidee ที่ระบุมีราคาเหมาะสม
- PV2: ประโยชน์ที่ฉันได้รับจาก Kinraidee คุ้มกับค่าใช้บริการที่ระบุ
- PV3: เมื่อพิจารณาค่าใช้บริการที่ระบุ Kinraidee ให้ความคุ้มค่าแก่ฉัน

### HT — เมื่อมีประสบการณ์ใช้ซ้ำ

แผนเริ่มต้นอาจติดตาม 2–4 สัปดาห์ แต่ช่วงเวลานี้เป็นข้อเสนอของโครงการ ไม่รับรองว่าเกิดนิสัยแล้ว ต้องบันทึกจำนวนครั้งและระยะเวลาที่ใช้จริงก่อนตีความ

ตัวอย่างร่างคำถามสำหรับผู้ใช้ซ้ำ:

- HT1: การใช้ Kinraidee เพื่อเลือกอาหารกลายเป็นความเคยชินของฉัน
- HT2: เมื่อเลือกอาหารไม่ออก ฉันเปิด Kinraidee โดยแทบไม่ต้องคิด
- HT3: การใช้ Kinraidee เป็นส่วนหนึ่งของกิจวัตรการเลือกอาหารของฉัน

### UB — พฤติกรรมการใช้จริง

กำหนดช่วงเดียวกัน เช่น 14 วันที่ผ่านมา แล้วเก็บจำนวนวันที่ใช้ จำนวนครั้งที่ใช้ และกิจกรรมที่ใช้ เช่น เลือกอาหารหรือเปลี่ยนเมนู ระบุด้วยว่าเป็นคำตอบจากผู้ใช้หรือข้อมูลระบบ

เริ่มจากแบบสอบถามติดตามหรือบันทึกการใช้ได้ การเพิ่ม telemetry ในแอปต้องกำหนดวัตถุประสงค์ ข้อมูลที่เก็บ และการเก็บรักษาก่อนตามแผนโปรเจกต์ ไม่ถือว่าเอกสารนี้อนุมัติให้เก็บ telemetry เพิ่ม

## 8. วิธีคำนวณคะแนน

### 8.1 คะแนนตัวแปรของผู้ตอบแต่ละคน

คำนวณค่าเฉลี่ยแยกตัวแปร เช่น PE มีสี่ข้อ:

```text
PE รายคน = (PE1 + PE2 + PE3 + PE4) / 4

ตัวอย่าง: (4 + 5 + 4 + 5) / 4 = 4.50 จาก 5
```

ทำแบบเดียวกันกับ EE, HM, FC, SI และ BI โดยใช้จำนวนข้อของแต่ละด้าน ทุกข้อในร่างนี้ให้คะแนนทิศทางเดียวกัน ไม่มีข้อกลับคะแนน

สำหรับรอบแรก กำหนดให้ผู้ตอบต้องตอบครบทุกข้อในด้านนั้นจึงคำนวณคะแนนด้านนั้น หากมี “ประเมินไม่ได้” หรือข้าม ให้เว้นคะแนนด้านนั้น ไม่แทนด้วย 0 หรือคะแนนกลาง 3 และยังรายงานคำตอบรายข้อที่ใช้ได้

### 8.2 คะแนนภาพรวมของกลุ่ม

นำคะแนนรายคนของด้านเดียวกันมาหาค่าเฉลี่ยและส่วนเบี่ยงเบนมาตรฐานของตัวอย่าง (SD) รายงานจำนวนผู้ตอบที่ใช้ได้ของแต่ละด้านด้วย

| ด้าน | จำนวนผู้ตอบที่ใช้ได้ (n) | ค่าเฉลี่ย (1–5) | SD |
|---|---|---|---|
| PE — ประโยชน์ | ยังไม่เก็บ | — | — |
| EE — ความง่าย | ยังไม่เก็บ | — | — |
| HM — ความเพลิดเพลิน | ยังไม่เก็บ | — | — |
| FC — ความพร้อม | ยังไม่เก็บ | — | — |
| SI — อิทธิพลทางสังคม | ยังไม่เก็บ | — | — |
| BI — ความตั้งใจใช้ต่อ | ยังไม่เก็บ | — | — |

PP1–PP7 และ SAT1 รายงานค่าเฉลี่ย จำนวนคำตอบ และการกระจายของคะแนนแยกรายข้อ สำหรับ SD เมื่อมีผู้ตอบที่ใช้ได้เพียงคนเดียว ให้ระบุว่าคำนวณไม่ได้

### 8.3 ถ้าต้องการแสดงเป็นคะแนน 0–100

```text
คะแนนแปลง = (ค่าเฉลี่ย − 1) / 4 × 100

ตัวอย่าง: PE = 4.50 → (4.50 − 1) / 4 × 100 = 87.50 จาก 100
```

นี่เป็นการแปลงเพื่อแสดงผล ไม่ใช่คะแนนทางการของ UTAUT2 และไม่ใช่ร้อยละของผู้ใช้ที่ยอมรับระบบ

## 9. วิธีอ่านผลและข้อจำกัด

- PE สูง: ผู้ใช้รับรู้ประโยชน์ แต่ยังต้องดู PP รายข้อว่าประโยชน์มาจากอะไร
- EE ต่ำ: ตรวจความคิดเห็นเรื่องขั้นตอน การกรอกเงื่อนไข และการเปลี่ยนตัวเลือก
- HM ต่ำ: ตรวจประสบการณ์เปิดการ์ด ทั้งนี้ความสนุกไม่ใช่หลักฐานว่าระบบไร้ประโยชน์
- FC ต่ำ: ตรวจอุปกรณ์ อินเทอร์เน็ต ความรู้ และแหล่งช่วยเหลือ แยกจากความง่ายของหน้าจอ
- BI ต่ำ: อ่านเหตุผลที่ไม่กลับมาใช้ แม้ด้านอื่นอาจมีคะแนนสูง
- SI ตอบได้น้อย: รายงานว่าแอปยังไม่มีข้อมูลอิทธิพลทางสังคมเพียงพอ ไม่แทนด้วยคะแนนกลาง

ไม่รวม PE + EE + HM + FC + SI + BI เป็น “คะแนน UTAUT2 รวม” และไม่สรุปจากค่าเฉลี่ยอย่างเดียวว่าด้านใดเป็นสาเหตุให้ใช้ต่อ การทดสอบความสัมพันธ์ต้องมีแผนวิเคราะห์และตัวอย่างที่เหมาะสม

เอกสารนี้ยังไม่กำหนดคะแนนผ่าน/ไม่ผ่าน หากต้องใช้เกณฑ์ ต้องตกลงและบันทึกก่อนเก็บข้อมูล ไม่ตั้งเกณฑ์หลังเห็นผล หากใช้เป็นงานวิจัย ต้องตรวจความเชื่อมั่น ความเที่ยงตรงของการวัด และความเหมาะสมของการวิเคราะห์เพิ่มเติม
